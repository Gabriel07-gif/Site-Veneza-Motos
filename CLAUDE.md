# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Static marketing / catalog site for **Veneza Motos e Veículos** (motorcycle & car dealer, Fortaleza/CE, Brazil). No build step, no framework, no package manager — plain HTML/CSS/JS deployed as static files. Deploy target is Netlify (see [_redirects](_redirects)).

Site language is **pt-BR** — all UI copy, alt text, meta descriptions, and JSON-LD content must be in Portuguese.

## Running locally

Any static server works. Two common options:

```powershell
# Python
python -m http.server 8000

# Node
npx serve .
```

Then open `http://localhost:8000/`. There are no tests, no linter, no build. Changes are visible on refresh.

## Architecture

### Two page templates

1. **[index.html](index.html)** (~1100 lines) — the single landing page. Contains all sections: intro splash, hero, stock filter, catalog, services, about, contact form. Uses [styles.css](styles.css) + [intro.css](intro.css). Driven by [script.js](script.js) + [intro.js](intro.js) + [moto3d.js](moto3d.js).

2. **`<vehicle-slug>.html`** (~250 lines each) — one file per vehicle for SEO/sharing. All 17 vehicle pages are near-identical copies of the same Bootstrap-based template. They use [vehicle-nav.css](vehicle-nav.css) + [vehicle-page.css](vehicle-page.css) and load [vehicle-fullscreen.js](vehicle-fullscreen.js) + [vehicle-share.js](vehicle-share.js). Bootstrap 5.3 and Feather Icons are loaded from CDN — this is the **only** part of the site that hits external JS.

**Consequence**: adding/editing a vehicle means (a) hand-editing its HTML file, (b) updating [sitemap.xml](sitemap.xml), and (c) updating the catalog/stock cards inside [index.html](index.html). There is no data source — vehicle data is duplicated in HTML.

### CSP is strict

[index.html](index.html) line 12 declares a Content Security Policy that only allows scripts from `'self'` and `https://unpkg.com`. **Adding a new CDN script requires updating the CSP.** Vehicle pages do not set CSP (they use Bootstrap from jsdelivr).

### script.js orchestration

[script.js](script.js) is a single ~1080-line file with ~25 top-level `init*` / handler functions, all wired up inside one `DOMContentLoaded` handler wrapped in `try/catch`. Key entry points to know:

- `filterVehicles(type)` / `filterCatalog()` — stock and catalog filtering by category/transmission (called from inline `onclick=` in [index.html](index.html))
- `applyVehicleImages()` / `applyCatalogImages()` — sets CSS `background-image` on `.vehicle-image` / `.catalog-card-image` divs from `data-src` attributes (lazy-load pattern)
- `openContactModal(vehicleName)` — triggers the contact modal and pre-fills the vehicle name
- `handleSimulationFormSubmit` / `handleContactFormSubmit` — form → `wa.me` deep link (no backend)
- `applyTheme(theme)` — dark/light toggle persisted in `localStorage` under `veneza_theme`
- `populateSimulationVehicleOptions()` — reads vehicle cards from the DOM to populate the simulation form's `<select>`

Vehicle-detail pages have their own theme toggle using `localStorage` key `veneza_vehicle_theme` (inline script at the bottom of each vehicle HTML).

### The three animation subsystems

They are independent and can be toggled/removed one at a time:

- **[intro.js](intro.js) / [intro.css](intro.css)** — full-screen splash overlay (canvas particles rising + brand reveal + 3.8s auto-dismiss). Runs once per page load on `index.html` only. IIFE, no exports.
- **[moto3d.js](moto3d.js)** — ES module that mounts a real Three.js scene into `#hero-3d-mount` (transparent canvas, ACESFilmic tone mapping, studio lights, restricted OrbitControls). Three.js is **vendored locally** in `vendor/` (`three.module.min.js` + `three.core.min.js` + `OrbitControls.js` with its `'three'` import rewritten to a relative path) so the strict CSP stays `script-src 'self'` — do not swap it for a CDN import. The motorcycle is a **procedural model generated by the img2threejs pipeline** from `moto-hero-3d.png`: `vendor/createMotoModel.js` exports `createMotoTrailVenezaModel()` (~52 meshes incl. instanced spokes/tread, ~43k tris); its sculpt spec + image analysis live in `vendor/img2threejs-spec/` for provenance. The factory's procedural canvas textures are disabled (`makeProceduralTextureSet` returns null — the auto-extracted palette was wrong and painted the bike brown); instead moto3d.js's `aplicarMateriaisPartilhados()` replaces every mesh material with **4 shared `MeshStandardMaterial`s** (blue gloss / matte black / metallic silver / headlight) keyed by component id — edit colors there, not in the factory. Rendering is on-demand (only when OrbitControls fire `change`, the idle sway is active, or after a resize), shadows are fully off (CSS contact shadow instead), pixel ratio is capped at 2, and antialias/idle-sway are disabled on low-end devices. It is a stylized approximation, not photogrammetry — regenerate via the img2threejs repo using that spec if it needs refinement. Falls back to `moto-hero-3d.png` (`.hero-3d-fallback` in styles.css) when WebGL is unavailable. The hero container has **no box** (no border/background) — the bike floats over the hero gradient with a CSS glow (`::before`) and contact shadow (`::after`). Render loop pauses off-viewport and on hidden tabs. Hero entry animations in styles.css are gated on `body.intro-done`, which intro.js adds when the splash is dismissed.
- **`vehicle-fullscreen.js`** — click-to-zoom lightbox on vehicle-detail pages. Uses Bootstrap's Carousel API for image navigation and forces `interval: false` to prevent auto-advance.

### CSS variables & theming

Both themes are defined at the top of [styles.css](styles.css) as CSS custom properties on `:root` and `body[data-theme="dark"]`. **`--muted` must remain a near-black value** (currently `#1e293b`) in light mode — it is used for body copy across the site, not just muted labels. A previous change to `#6b7280` made the whole site look washed out.

### Images

Optimized WebP images live under `Imagens otimizadas/Imagens motos/` and are referenced by number (e.g. `321.webp`, `422.webp`). The mapping from filename to vehicle is done inline in each vehicle HTML file. `moto-hero-3d.png` at the repo root is the hero image consumed by [moto3d.js](moto3d.js).

## Editing conventions

- Every vehicle HTML must ship with a matching `Motorcycle`/`Car` JSON-LD block in `<head>` — search engines use it for the Google Search listing. If you change the price, model, or images, update the JSON-LD too.
- Nav links in vehicle pages all point to `index.html#<section>` (not `#<section>` alone) so they work from a subpage.
- WhatsApp links are hand-crafted `https://wa.me/5585986114901?text=...` URLs with a URL-encoded Portuguese message that mentions the specific vehicle. When cloning a vehicle page, update the message text.
- Do **not** introduce a build tool, framework, or package manager without a reason — the site is intentionally zero-dependency for portability and simple deploys.
